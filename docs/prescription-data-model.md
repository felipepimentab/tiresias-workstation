# Prescription data objects and units

Your five-part model is structurally correct, with three important refinements:

- Audiogram thresholds are **dB HL**, not dB SPL.
- Prescription **gain is dB**, indexed by input levels in **dB SPL**.
- Headroom and SoftClip form an **output-stage configuration**: reference-level
  conversion plus output limiting, not the B1–B8 detector calibration.

This reference follows `tiresias-eval` at revision `309a644`. The five objects now have separate persistent library entries and editors.
See [Fitting library](fitting-library.md) for CRUD, generation, provenance,
protected defaults, migration, and board loading.

## 1. Audiogram

- **Meaning / stage:** Hearing thresholds for each ear and frequency; the input
  to the prescription rule. dB HL expresses threshold relative to a standardized
  hearing reference, not absolute acoustic pressure. Conversion to dB SPL is
  frequency/reference dependent, not one universal offset.
- **Representation / units:** A frequency vector in **Hz**, with aligned left
  and right threshold vectors in **dB HL**; immutable tuples in Python and
  numeric arrays in JSON.
- **Creation / dependencies:** Entered from hearing-threshold measurements or a
  reference profile, such as the eval repository's Bisgaard audiograms. Depends
  on the measured/reference thresholds and their frequency/ear assignments;
  not the destination DSP board.
- **Workstation object:** `Audiogram`, with `frequencies_hz`,
  `left_levels_db_hl`, and `right_levels_db_hl`.

## 2. Prescription target

- **Meaning / stage:** Desired gain for each ear, frequency band, and acoustic
  input level; the output of CAMFIT, before device-specific compilation.
- **Representation / units:** Band centres/edges in **Hz**; input-level axis in
  **dB SPL**; gain matrices in **dB**, indexed `[band][input level]` separately
  for each ear. Timing metadata is in **ms**. The current target has two ears,
  nine bands, and 121 input levels.
  For example, 65 dB SPL input plus 10 dB gain gives 75 dB SPL target output.
- **Creation / dependencies:** Generated by the pinned pyClarity CAMFIT adapter
  from the audiogram, rule version/settings, fitting filterbank, level grid,
  and interpolation/endpoint policies. Does **not** depend on the measured
  EVAL or Tiresias detector calibration. Timing values are recipe settings,
  not quantities inferred from the audiogram.
- **Workstation object:** `PrescriptionTarget`, the portable fitting intent.

## 3. Device detector calibration

- **Meaning / stage:** A measured, per-band relationship between the DSP's
  internal RMS detector levels and equivalent acoustic input levels. It is
  acquired independently of the audiogram and used during LUT compilation.
- **Representation / units:** Paired **dBFS detector** and **equivalent dB SPL**
  arrays for each band, test frequencies in **Hz**, endpoint policies, and
  measurement/provenance metadata. Electrical bench measurements use **dBV**.
  dBFS must identify the signal location and detector convention; it is not a
  device-wide, universally interchangeable level scale.
- **Creation / dependencies:** Identified from controlled stationary-tone
  unity/identification measurements. Depends on the board, analogue/ADC gains,
  filterbank, detector implementation/settings, and measurement setup. The
  eval data describe the **ADAU1787 EVAL configuration**, not an independently
  established microphone-to-SPL calibration of the Tiresias board.
- **Workstation object:** `DeviceCalibration` contains eight `CalibrationBand`
  measurements with paired axes and endpoint policies. It is stored independently
  and selected during compilation. The Eval measurements are a protected default.
  `DspMapping` records conversion results; compiled artifacts additionally retain
  the complete selected calibration snapshot.

## 4. Compiled DSP prescription

- **Meaning / stage:** Device-specific compressor LUTs **and their associated
  bias gains**, generated before loading the board. Calibration is incorporated
  into these values, not uploaded as an independent runtime correction table.
- **Representation / units:** Eight LUTs of 34 **dimensionless linear gain**
  values and three linear bias gains, encoded as four-byte, big-endian
  **SigmaDSP 5.23 fixed-point words**. LUT positions correspond to fixed
  **dBFS detector** coordinates. Inspection data also retain gains in **dB**;
  JSON exports actual payload bytes as hex strings. Total: 1,100 bytes.
- **Creation / dependencies:** Map detector knots through calibration, sample
  the target, fit the coarse LUT, split excess gain into three shared bias
  stages, then quantize. Depends on the target, selected ear, detector
  calibration, DSP topology/grid, numeric limits, and compiler implementation.
  The biases preserve desired gain while keeping LUT values representable;
  they are not the output Headroom setting.
- **Workstation objects:** `CompiledDspPrescription` retains the generated
  artifact, complete calibration snapshot, compiler version and contract CRC.
  `Prescription` holds the parameter bytes;
  `DspMapping` explains their derivation. Changing calibration normally requires
  regenerating **both LUTs and biases**. Keep their target/calibration/program
  provenance together, as the eval manifests do with input hashes.

## 5. Output-stage configuration

- **Meaning / stage:** Global output reference scaling and peak limiting,
  applied after band recombination/phase compensation. It is not another
  audiogram prescription or a replacement for detector calibration.
- **Headroom:** A constant multiplier before SoftClip. Its setting is described
  in **dB gain/attenuation** and encoded as one **linear 5.23 word**. Eval uses
  **−22 dB**: −20 dB converts the CEC1 input reference (0 dBFS = 100 dB SPL)
  to its output reference (0 dBFS = 120 dB SPL); −2 dB adds campaign margin.
- **SoftClip:** A global peak-dynamics gain curve: transparent below its
  threshold, compressive above it, with an output ceiling. Threshold/ceiling
  coordinates use **dBFS peak**, gains use **dB** for inspection, and the DSP
  stores **45 linear 5.23 gain words**.
  Hold/decay parameters must also match the configured DSP implementation.
- **Creation / dependencies:** Derived from the output reference, desired
  limiting behavior, headroom margin, and SoftClip detector/table conventions.
  Headroom and SoftClip must be configured coherently. Eval's documented
  campaign candidate is the word-aligned **nominal** SoftClip table; an
  experimental detector-calibrated table remains diagnostic only because its
  measured map was waveform dependent.
- **Workstation object:** `OutputStageConfiguration` is stored independently
  and compiles Headroom plus the complete nominal SoftClip curve. The Eval
  configuration is a protected default. Output values are loaded as a separate
  two-parameter operation, not included in the 11-parameter compiled fitting.
  The exported hold/decay remain fixed program prerequisites. These engineering
  settings do not establish actual receiver SPL or guarantee safe acoustic output.

## Dependency and reuse rule

```text
Audiogram ──CAMFIT──> Prescription target ─┐
Device detector calibration ─────────────┼─compile─> DSP LUTs + bias gains
DSP specification + selected ear ────────┘

DSP output path: band recombination/phase compensation → Headroom → SoftClip
```

Store the five responsibilities separately, but track their dependencies.
Reuse the **target** across compatible implementations; recompile for another
board's calibration. Identical LUT bytes are reusable only when the relevant
detector mappings and DSP configurations are equivalent. Changing output
Headroom/SoftClip cannot generally correct mismatched per-band input detection.
